# uniLog — Industrial PIM Enrichment Engine

Turns a supplier's raw catalog export — six columns of inconsistent identity data — into the
client's 252-column commerce-ready delivery format, with a provenance trail behind every
published value.

The design principle running through all seven stages: **AI proposes, deterministic code
disposes.** A language model is used at exactly one point — reading a technical document and
proposing candidate facts. It never writes to the output. Every value it proposes passes
through rule-based normalization, conflict detection and a quality gate before any column is
filled.

## Pipeline

| Stage | Module | What it does |
|---|---|---|
| 1 | `src/cleaner.py` | Strips placeholders and ERP suffixes; resolves brand and manufacturer |
| 2 | `src/taxonomy.py` | Assigns category, Dept/Class/Fine/Classpath and per-category target attributes |
| 3 | `src/fetcher.py` | Finds and downloads manufacturer documentation; marketplace deny-list; PDF/HTML text extraction |
| 4 | `src/extractor.py` | LLM fact extraction with confidence, source snippet and page; rate-limited |
| 5 | `src/normalizer.py` | Deterministic UOM, material, fraction and enum standardization |
| 6 | `src/validator.py` | Quality score 0–100 and traffic-light routing |
| 7 | `src/mapper.py` + `src/exporter.py` | Maps facts into the 252-column delivery format |

Routing: 🟢 `AUTO_APPROVED` ≥ 80 publishes · 🟡 `HUMAN_REVIEW` 50–79 queues with a reason ·
🔴 `FAILED` < 50 goes to research.

## Setup

```bash
python -m venv venv && source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                              # then add your Gemini API key
```

## Run

```bash
python main.py                 # full catalog
python main.py --limit 25      # smoke test on the first 25 products
python main.py --fetch         # enable Stage 3 document retrieval
python main.py --no-ai         # plumbing only, no API calls
python main.py --rpm 15        # override the extraction rate limit
```

Tests:

```bash
python tests/test_cleaner.py && python tests/test_pipeline.py
```

## Output

```
data/output/FINAL_MASTER_CATALOG.csv    252 columns, one row per input product
data/intermediate/extracted_facts.csv   evidence graph — value, confidence, snippet, page
data/intermediate/normalized_facts.csv  before and after every value
data/intermediate/validation_report.csv quality dashboard
data/intermediate/retrieval_log.csv     Stage 3 source audit
logs/pipeline_<timestamp>.log           structured run log
```

These are regenerated by every run and are not tracked in git.

## UI

`ui/index.html` — upload screen that parses a supplier CSV in the browser, checks the header
against the input schema and previews rows before a run is committed. Open it directly; no
build step.
